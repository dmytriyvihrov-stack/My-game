⛔ **`prototype/grimtoll_slice.html` IS 3.4 MB NOW, NOT 30.2, AND THE ART KEYS ARE NOT IN IT.**
Grepping the prototype for `EVJ4` or `POR03` will say the art is missing when it is not. It is in
**`art/embed/art_data.js`** (12.96 MB) and **`art/embed/j_pack.js`** (13.85 MB), both TRACKED, both
generated by `art/embed.ps1`, loaded by two classic script tags in the head of the prototype.

⛑ **NOTHING ABOUT WHAT SHIPS CHANGED, AND THAT WAS THE USER'S OWN CONDITION** (*"would it be
working when i upload it to the git? And will it be still easy to make build for itchi and
similar?"*). GitHub Pages serves `index.html` and the itch upload is a zip with `index.html` at its
root; both are GENERATED by `tools/build_site.ps1`, which already poured the audio into a marker and
now pours the art the same way. **Measured: 350 `data:image` payloads in the built page against the
shipped page's 350**, and it boots with every art table at its old count. `build_itch.ps1` calls
`build_site.ps1 -Player` and inherited it for free.

⛑ **NOT ONE LINE OF GAME CODE CHANGED, AND THE REASON IS A LANGUAGE RULE WORTH KNOWING: a top-level
`const` in a CLASSIC script is a GLOBAL LEXICAL binding**, visible to every later script in the
document. So `ART`, `JSTAGE_ART`, `WORLD_BG` and the rest are exactly as visible as when they sat
inside the one inline script. ⛔ **Which is why `defer` and `type=module` are forbidden on those two
tags** - either one drops the game silently to `HASART`'s procedural fallback. ⚑ And that fallback
(`typeof ART!=='undefined'`, written years before this) is why a missing file is a degraded picture
rather than a crash.

⛑ **IT RETIRED A HAZARD THIS PROJECT HAD BEEN MANAGING RATHER THAN FIXING.** `inject.ps1` and
`inject_j_pack.ps1` each read the whole 30 MB prototype and wrote it whole back, each carrying its
own warning that this *"is the exact shape that erases a parallel session's work. Ask first."* They
forward to `art/embed.ps1` now and touch nothing shared, so the `claim.ps1` gate went with the
danger, and #209's careful reason for a SECOND injector (*"two desks that both run it produce the
conflict nothing can resolve"*) became structural: two blocks, two files, nothing to collide over.
`docs/PARALLEL_SESSIONS.md` item 2 was *"solved by isolation"* and is solved outright.

⚠ **`art/embed/` IS TRACKED AND MUST STAY TRACKED.** `art/src/` and `art/out/` are ignored and the
gitignore's own paragraph used to say the art was "already INSIDE index.html". A desk is a FRESH
CHECKOUT: ignore `art/embed/` and every new desk gets a game with no art and no error saying why.
⚠ They are also `-text` in `.gitattributes`, because `* text=auto` checked them out as CRLF while
`embed.ps1` writes LF, so `git status` reported 27 MB of pure line-ending churn after every rebuild.

## The two bugs, and they were the same bug twice

⛔ **SYNTAX INSIDE A COMMENT THAT ENDS THE COMMENT.** The generated header named its own marker as
`/*__ART_DATA__*/` inside a `/* */` block and the nested terminator closed it **12 MB early**; and
the HTML comment introducing the two tags contained a literal script tag, so the inline-script
scanner matched THAT and tried to parse English as JavaScript (*"Unexpected identifier 'the'"*).
Both were named in under a second by a gate; neither by the browser, which just showed a page with
no art and no error.

⛑ **SO THE GATE GREW TO FIT, WHICH IS THE HABIT WORTH KEEPING.** `tools/dev/jscheck.js` follows
`<script src>` now and blanks HTML comments first (blanks, not deletes, so line numbers survive). A
checker that only read inline scripts would have gone on printing *0 errors* over a build whose
paintings did not parse - and it did, for one round. **Proved by making it fire**: `const oops = ;`
appended to `j_pack.js` reports and exits 1; restored, 3 scripts, 0 problems.
